## 0. 先把五件事串成一条线

```
                       ┌──────────────────────┐
   总线上的差分帧 ────►│  验收过滤器（14 组）  │
                       └──────────┬───────────┘
                                  │ 命中
                                  ▼
                       ┌──────────────────────┐
                       │ FIFO0 / FIFO1（3 级） │──► 中断 ──► CPU 取走
                       └──────────────────────┘
                                  ▲
                    位时间/同步决定"在第几个 tq 采样"
                                  ▲
                    测试模式决定"帧发去哪、收什么"
                                  ▲
                    TTCM 决定"给帧盖什么时间戳"
```

用生活打比方：

| 概念 | 比喻 | 一句话 |
|---|---|---|
| 过滤器 | 小区门禁 | 只放"符合规则"的帧进来 |

| 中断 | 门铃 | 有人来了通知 CPU |

| TTCM | 给访客盖"到达时间"章 | 记录这一帧是什么时候到的 |

## 1. 过滤器：CAN 的"门禁规则"

### 1.1 一句话理解

CAN 的过滤器不是"地址匹配"，而是**位模式匹配**：

> 一帧里有 **ID（11/29 位）+ IDE（标准/扩展）+ RTR（数据/远程）** 这几类位。
> 你想固定哪些位，就把掩码对应位写 1；不想管的位，掩码写 0（"随便"）。

所以过滤器本质是：

```
收到一帧 ──► (帧的 ID 位) AND (掩码)  ==  (过滤器的 ID 位) AND (掩码) ?
                 │
                 ├─ 相等 → 命中，存入指定 FIFO
                 └─ 不等 → 丢弃，CPU 根本不知道
```

### 1.2 硬件家底（F103）

| 资源 | 数量 | 说明 |
|---|---|---|
| 过滤器组（bank） | **14 组**（CAN1） | F105/107 共 28 组，CAN1 用 0~13，CAN2 用 14~27 |
| 每组寄存器 | 2 个 32 位：`CAN_FxR1`、`CAN_FxR2` | 存 ID / 掩码 / 第二个 ID |
| 每组容量（32 位模式） | 1 个"ID+掩码"，或 2 个"精确 ID" | 掩码模式 / 列表模式 |
| 每组容量（16 位模式） | 2 个"ID+掩码"，或 4 个"精确 ID" | 更省 bank，但字段更绕 |
| 命中优先级 | **bank 号越小越优先** | 多个过滤器都命中时，低编号决定 FIFO 和 FMI |

控制寄存器（都在 `CAN1` 下，CAN2 的过滤器也通过 CAN1 的寄存器配）：

| 寄存器 | 关键位 | 作用 |
|---|---|---|
| `CAN_FMR` | `FINIT`（bit0） | 过滤器初始化模式；=1 才能改过滤器 |
| | `CAN2SB[5:0]`（bit13:8） | CAN2 从哪一组 bank 开始（F105/107） |
| `CAN_FM1R` | 每个 bank 1 位 | 0=掩码模式，1=列表模式 |
| `CAN_FS1R` | 每个 bank 1 位 | 0=16 位，1=32 位 |
| `CAN_FFA1R` | 每个 bank 1 位 | 0=存 FIFO0，1=存 FIFO1 |
| `CAN_FA1R` | 每个 bank 1 位 | 0=未激活，1=激活 |
| `CAN_FxR1/FxR2` | 32 位 | ID / 掩码 / 列表 ID |

> 记住：**FA1R 没置 1 的 bank 等于不存在**。复位后所有 bank 都没激活，所以"不配过滤器 = 一帧都收不到"。

### 1.3 32 位掩码模式（最常用）

**寄存器布局**（`CAN_FxR1` 存 ID，`CAN_FxR2` 存掩码，两者位定义相同）：

```
 31          21 20              3 2   1 0
┌──────────────┬─────────────────┬───┬───┬─┐
│ STID[10:0]   │ EXID[17:0]      │IDE│RTR│0│
└──────────────┴─────────────────┴───┴───┴─┘
  标准 ID 11 位   扩展 ID 18 位   0=标准 0=数据
                                  1=扩展 1=远程
```

- **标准帧**：`STID` 填 11 位 ID，`EXID` 填 0，`IDE=0`；
- **扩展帧**：`STID = ExtId[28:18]`（高 11 位），`EXID = ExtId[17:0]`（低 18 位），`IDE=1`；
- **RTR**：0=数据帧，1=远程帧；
- **掩码位 = 1** 表示"这一位必须和 ID 寄存器一致"，**= 0** 表示"这一位随便"。

**几个最常用的例子**：

| 需求 | ID 寄存器（32 位） | 掩码（32 位） | 说明 |
|---|---|---|---|
| 收所有帧 | `0x00000000` | `0x00000000` | 全 0 掩码 = 什么都收（教程常用） |
| 只按 11 位 ID `0x123` 过滤（不区分标准/扩展、数据/远程） | `0x123 << 21 = 0x24600000` | `0x7FF << 21 = 0xFFE00000` | 只比较 11 位 ID |
| 只收标准 ID `0x123` 的**数据帧** | `0x24600000` | `0xFFE00000 + 0x6 = 0xFFE00006` | 要求 IDE=0 且 RTR=0 |
| 只收标准 ID `0x123` 的**标准帧** | `0x24600000` | `0xFFE00000 + 0x4 = 0xFFE00004` | 再要求 IDE=0 |
| 收 `0x100~0x1FF` 范围 | `0x100 << 21 = 0x20000000` | `0x700 << 21 = 0xE0000000` | 低 8 位 ID 随便 |
| 只收扩展 ID `0x1234567` | `(0x1234567 << 3) + 0x4` | `(0x1FFFFFFF << 3) + 0x4` | IDE=1 要求扩展帧 |

> 注意：范围过滤 `0x100~0x1FF` 只固定了 ID 的高 3 位，**IDE/RTR 是"随便"**，所以扩展帧只要基础 ID 落在范围内也会被收。要"只要标准帧"，掩码再或上 `0x4`。

**标准库代码**（只收标准 ID `0x123` 的数据帧，存 FIFO0）：

```c
static void CAN_Filter_Config(void)
{
    CAN_FilterInitTypeDef f;
    uint32_t id   = (0x123U << 21);                       // STID 在 bit31:21
    uint32_t mask = (0x7FFU << 21) | (1U << 2) | (1U << 1); // 11 位 ID + IDE=0 + RTR=0

    f.CAN_FilterNumber = 0;                      // 用 0 号 bank
    f.CAN_FilterMode   = CAN_FilterMode_IdMask;  // 掩码模式
    f.CAN_FilterScale  = CAN_FilterScale_32bit;  // 32 位
    f.CAN_FilterIdHigh = (uint16_t)(id >> 16);   // 0x2460
    f.CAN_FilterIdLow  = (uint16_t)(id & 0xFFFF);// 0x0000
    f.CAN_FilterMaskIdHigh = (uint16_t)(mask >> 16); // 0xFFE0
    f.CAN_FilterMaskIdLow  = (uint16_t)(mask & 0xFFFF); // 0x0006
    f.CAN_FilterFIFOAssignment = CAN_FIFO0;      // 命中后进 FIFO0
    f.CAN_FilterActivation = ENABLE;             // 激活
    CAN_FilterInit(&f);
}
```

> 注意 `CAN_FilterIdHigh` 就是寄存器 `FxR1[31:16]`，`IdLow` 是 `FxR1[15:0]`；库函数只是把它们拼成 32 位写进去。

### 1.4 32 位列表模式（精确名单）

列表模式下，`FxR1` 和 `FxR2` **都是 ID**，没有掩码：

```c
// 只收 0x123 和 0x456 两个精确 ID（标准帧）
f.CAN_FilterMode  = CAN_FilterMode_IdList;
f.CAN_FilterScale = CAN_FilterScale_32bit;
f.CAN_FilterIdHigh = (uint16_t)((0x123U << 21) >> 16);
f.CAN_FilterIdLow  = 0x0000;
f.CAN_FilterMaskIdHigh = (uint16_t)((0x456U << 21) >> 16); // 列表模式：这是第二个 ID
f.CAN_FilterMaskIdLow  = 0x0000;
```

- 一个 bank 放 **2 个精确 ID**；
- 14 个 bank 最多 **28 个精确 ID**；
- 列表模式适合"只关心几个固定报文"的场景（如只收 0x101、0x102、0x201）。

### 1.5 16 位模式（省 bank，但字段更绕）

16 位过滤器里，一个 16 位单元的布局是：

```
 15          5 4   3 2   0
┌─────────────┬───┬───┬────┐
│ STID[10:0]  │IDE│RTR│EXID│
└─────────────┴───┴───┴────┘
```

- 16 位**掩码模式**：每组 bank 放 **2 个** "ID+掩码"：
  - `FxR1[15:0]` = 第 1 个 ID，`FxR1[31:16]` = 第 1 个掩码；
  - `FxR2[15:0]` = 第 2 个 ID，`FxR2[31:16]` = 第 2 个掩码；
- 16 位**列表模式**：每组 bank 放 **4 个** 精确 ID：
  - `FxR1[15:0]`、`FxR1[31:16]`、`FxR2[15:0]`、`FxR2[31:16]`。

> **16 位模式对扩展帧不友好**：它只有 `EXID[17:15]` 三位，最多比较扩展 ID 的高 3 位，没法精确过滤 29 位 ID。要精确过滤扩展帧，用 32 位模式。

标准库结构体的命名有个坑：16 位**掩码模式**下，`IdLow` + `MaskIdLow` 是第 1 个过滤器，`IdHigh` + `MaskIdHigh` 是第 2 个；16 位**列表模式**下，这四个字段依次是第 1~4 个 ID。它们**不是"高 16 位/低 16 位"的意思**。看 `CAN_FilterInit` 源码 318~326 行就明白了：

```c
FR1 = (MaskIdLow  << 16) | IdLow;
FR2 = (MaskIdHigh << 16) | IdHigh;
```

16 位掩码模式示例（两个标准 ID，各用 0x7FF 掩码）：

```c
uint16_t id1 = (uint16_t)(0x123U << 5);   // STID 在 bit15:5
uint16_t id2 = (uint16_t)(0x456U << 5);
uint16_t m   = (uint16_t)(0x7FFU << 5);   // 0xFFE0

f.CAN_FilterScale = CAN_FilterScale_16bit;
f.CAN_FilterIdLow      = id1;
f.CAN_FilterMaskIdLow  = m;
f.CAN_FilterIdHigh     = id2;
f.CAN_FilterMaskIdHigh = m;
```

**容量对比**：

| 模式 | 每组 bank | 14 组总共 |
|---|---|---|
| 32 位掩码 | 1 个 ID+掩码 | 14 个掩码过滤器 |
| 32 位列表 | 2 个 ID | 28 个精确 ID |
| 16 位掩码 | 2 个 ID+掩码 | 28 个掩码过滤器 |
| 16 位列表 | 4 个 ID | 56 个精确 ID |

### 1.6 配置流程（库函数帮你做了什么）

```c
CAN_FilterInit(&f);
```

内部动作（对应源码 292~376 行）：

```
1. FMR |= FINIT            // 进入过滤器初始化模式
2. FA1R &= ~bank位          // 先关掉这个 bank
3. 按 Scale 写 FS1R、FxR1/FxR2
4. 按 Mode 写 FM1R
5. 按 FIFOAssignment 写 FFA1R
6. 按 Activation 写 FA1R
7. FMR &= ~FINIT           // 退出初始化模式
```

**顺序很重要**：`FINIT=1` 时过滤器不工作，配置完必须清 0；库函数已经处理，但你要知道"运行中改过滤器必须先置 FINIT，否则写入无效"。

多个 bank 就调用多次：

```c
for (uint8_t i = 0; i < 3; i++) {
    f.CAN_FilterNumber = i;
    // 分别填不同的 ID/掩码/FIFO
    CAN_FilterInit(&f);
}
```

### 1.7 常见坑（按出现频率排序）

| 现象 | 原因 | 解决 |
|---|---|---|
| 发得出去，一帧都收不到 | 没配过滤器 / bank 没激活 / `FINIT` 没清 | 先配一个"全收"过滤器验证链路 |
| 只收到一部分 | 掩码写太严 / ID 没左移 21 位 / 忘记 IDE/RTR 位 | 打印 `FxR1/FxR2` 对照位布局 |
| 收到了不该收的 | 掩码该 1 的位写了 0 / 范围过滤没限制 IDE | 收紧掩码 |
| 改过滤器不生效 | 运行中直接写 `FxR`，没进 `FINIT` | 重新调用 `CAN_FilterInit` |
| CAN2 收不到 | 没调 `CAN_SlaveStartBank()` / bank 号没从 14 开始 | F105/107 先设起始 bank |
| 多个过滤器都命中，FIFO 不对 | 低 bank 优先，先命中的决定 FIFO | 调整 bank 顺序 |
| 16 位模式 ID 对不上 | 忘了 `STID << 5`，或 High/Low 搞反 | 对照 1.5 节布局 |

### 1.8 调试顺序（建议背下来）

1. **先全收**：`ID=0, Mask=0`，确认中断/FIFO/读函数没问题；
2. **再精确**：只收一个 ID，确认掩码位；
3. **再加条件**：加 IDE/RTR 限制；
4. **再看 FMI**：用 `RxMessage.FMI` 确认命中的是哪个 bank；
5. **最后做分流**：不同 bank 配不同 FIFO，做优先级分流。

## 2. 测试模式：不发到总线，也能把驱动跑通

### 2.1 四种模式一张表

| 模式 | `CAN_Mode` | `SILM` | `LBKM` | 帧发到总线？ | 收总线？ | ACK | 用途 |
|---|---|---|---|---|---|---|---|
| 正常 | `CAN_Mode_Normal` | 0 | 0 | 是 | 是 | 正常 | 正常组网 |
| 回环 | `CAN_Mode_LoopBack` | 0 | 1 | **否**（内部环回） | 内部 | 自己 ACK 自己 | 单板自测 |
| 静默 | `CAN_Mode_Silent` | 1 | 0 | 否（TX 隐性） | 是 | **不发 ACK** | 旁听/抓包 |
| 静默+回环 | `CAN_Mode_Silent_LoopBack` | 1 | 1 | 否 | 内部 | 内部自测，不对外 ACK | 完全隔离自测 |

> `SILM` 和 `LBKM` 是 `CAN_BTR` 的 bit31/bit30；标准库把 `CAN_Mode` 左移 30 位写进去。

### 2.2 怎么进入/退出

这两个位**只能在初始化模式（INRQ=1）下写**。标准库的做法是重新 `CAN_Init`：

```c
CAN_InitTypeDef init;
CAN_StructInit(&init);
init.CAN_Prescaler = 4;
init.CAN_Mode      = CAN_Mode_LoopBack;   // 改这里切换模式
init.CAN_SJW       = CAN_SJW_1tq;
init.CAN_BS1       = CAN_BS1_15tq;
init.CAN_BS2       = CAN_BS2_2tq;
CAN_Init(CAN1, &init);                     // 内部会进 INIT、写 BTR、再退出
```

退出测试模式：把 `CAN_Mode` 改回 `CAN_Mode_Normal`，再 `CAN_Init` 一次。

### 2.3 回环模式：自己给自己打电话

```
             ┌──────────────┐
  写邮箱 ───►│  bxCAN 发送   │
             └──────┬───────┘
                    │ 内部环回（不经过收发器/总线）
             ┌──────▼───────┐
             │  bxCAN 接收   │──► 过滤器 ──► FIFO ──► 中断
             └──────────────┘
```

**能验证什么**：

- 邮箱写入/发送完成标志（TXOK/RQCP）；
- 过滤器配置是否正确（**回环也要过过滤器**，不配就收不到自己的帧）；
- FIFO/中断/读函数；
- 位时序配置是否让 bxCAN 自己能收发（内部）；
- 软件状态机、协议解析。

**不能验证什么**：

- 收发器、双绞线、终端电阻、共地；
- 真实总线上的仲裁、ACK、错误帧；
- 电气层问题（波形、反射、共模）。

**最小自测代码**：

```c
void CAN_Loopback_Test(void)
{
    CanTxMsg tx = {0};
    CanRxMsg rx;

    tx.StdId = 0x123;
    tx.IDE   = CAN_Id_Standard;
    tx.RTR   = CAN_RTR_Data;
    tx.DLC   = 8;
    for (uint8_t i = 0; i < 8; i++) tx.Data[i] = i;

    uint8_t mb = CAN_Transmit(CAN1, &tx);
    if (mb == CAN_TxStatus_NoMailBox) return;

    while (CAN_TransmitStatus(CAN1, mb) == CAN_TxStatus_Pending);

    if (CAN_MessagePending(CAN1, CAN_FIFO0) > 0) {
        CAN_Receive(CAN1, CAN_FIFO0, &rx);
        // 期望 rx.StdId == 0x123, rx.DLC == 8, rx.Data[0..7] == 0..7
    }
}
```

**回环收不到的排查**：

1. 过滤器是否接受 0x123（用"全收"先排除）；
2. 是否真的进了 `CAN_Mode_LoopBack`（读 `CAN_BTR` 的 LBKM 位）；
3. `CAN_Transmit` 是否成功（返回的不是 NoMailBox）；
4. 是否等到了 `TXOK`（没等到说明波特率/初始化有问题）；
5. FIFO 是否被上一次测试占满（先读空）。

### 2.4 静默模式：只旁听，不发言

- 只接收，**不发 ACK、不发错误帧、不发数据**；
- 适合挂到在用总线上做"监听/抓包"，不会干扰总线；
- **注意**：如果总线上只有它一个接收者，发送方会因为收不到 ACK 而报 ACK 错误——它不是"正常节点"，只是"旁听者"；
- 静默模式仍然需要正确的波特率和过滤器。

### 2.5 测试模式的坑

| 坑 | 说明 |
|---|---|
| 回环成功就以为硬件没问题 | 回环不经过收发器和线缆，只证明 bxCAN 内部通路 |
| 静默模式当正常接收用 | 它不发 ACK，会让别的节点报错 |
| 运行中直接改 `CAN_BTR` | 必须先回初始化模式，标准库 `CAN_Init` 会处理 |
| 忘了切回 Normal | 上总线前检查 `CAN_BTR` 的 SILM/LBKM |
| 回环时用示波器看 TX 引脚 | 回环不把帧发到总线，TX 上可能看不到正常帧，别用示波器判断回环成败 |

## 3. 位时间：CAN 的"节拍"

### 3.1 一位分成四段，STM32 合并成三段

CAN 协议把 1 位分成 4 段：

```
|<------------------- 1 个位时间 (Nominal Bit Time) ------------------->|
| Sync_Seg |      Prop_Seg      |    Phase_Seg1    |    Phase_Seg2    |
|   1 tq   |<------- tseg1 ---------------------->|<---- tseg2 ------>|
                                                 ▲
                                              采样点
```

但 **STM32 的 bxCAN 不单独给 Prop_Seg 寄存器**，它把 `Prop_Seg + Phase_Seg1` 合并成 **BS1**，`Phase_Seg2` 就是 **BS2**：

```
位时间 N = 1 (Sync) + BS1 + BS2      （单位：tq）
采样点   = (1 + BS1) / N
```

| 段 | STM32 里叫什么 | 作用 |
|---|---|---|
| Sync_Seg | 固定 1 tq | 同步段，边沿应落在这里 |
| Prop_Seg + Phase_Seg1 | **BS1**（1~16 tq） | 补偿传播延迟 + 正向时钟误差 |
| Phase_Seg2 | **BS2**（1~8 tq） | 补偿负向时钟误差 |
| SJW | `CAN_SJW`（1~4 tq） | 每次再同步最多调整几个 tq |

### 3.2 寄存器与公式

`CAN_BTR` 字段：

| 字段 | 位 | 范围 | 含义 |
|---|---|---|---|
| `BRP[9:0]` | 9:0 | 0~1023 | 波特率预分频，实际分频 = BRP+1 |
| `TS1[3:0]` | 19:16 | 0~15 | BS1 = TS1+1 个 tq |
| `TS2[2:0]` | 22:20 | 0~7 | BS2 = TS2+1 个 tq |
| `SJW[1:0]` | 25:24 | 0~3 | SJW = SJW+1 个 tq |
| `LBKM` | 30 | — | 回环 |
| `SILM` | 31 | — | 静默 |

公式：

```
tq       = (BRP + 1) × tPCLK = CAN_Prescaler / fPCLK1
位时间 N = 1 + BS1 + BS2                （tq）
波特率   = fPCLK1 / (CAN_Prescaler × N)
采样点   = (1 + BS1) / N
```

> 库宏 `CAN_BS1_15tq` 的数值是 14（寄存器字段），表示"BS1 段 = 15 tq"；`CAN_BS2_2tq` 数值是 1，表示 2 tq。别把它当成"寄存器原值"。

### 3.3 500 kbps 完整算一遍（PCLK1=36 MHz）

```
Prescaler = 4
tq = 4 / 36 MHz = 111.11 ns
N  = 1 + 15 + 2 = 18 tq
位时间 = 18 × 111.11 ns = 2 µs  → 500 kbps
采样点 = (1 + 15) / 18 = 88.9%
```

配置：

```c
init.CAN_Prescaler = 4;
init.CAN_BS1 = CAN_BS1_15tq;
init.CAN_BS2 = CAN_BS2_2tq;
init.CAN_SJW = CAN_SJW_1tq;
```

### 3.4 常用波特率表（PCLK1=36 MHz）

| 波特率 | Prescaler | tq | BS1 | BS2 | N | 位时间 | 采样点 |
|---|---|---|---|---|---|---|---|
| 1 Mbps | 2 | 55.6 ns | 15 | 2 | 18 | 1 µs | 88.9% |
| 500 kbps | 4 | 111.1 ns | 15 | 2 | 18 | 2 µs | 88.9% |
| 250 kbps | 8 | 222.2 ns | 15 | 2 | 18 | 4 µs | 88.9% |
| 125 kbps | 16 | 444.4 ns | 15 | 2 | 18 | 8 µs | 88.9% |
| 100 kbps | 20 | 555.6 ns | 15 | 2 | 18 | 10 µs | 88.9% |
| 50 kbps | 40 | 1.111 µs | 15 | 2 | 18 | 20 µs | 88.9% |
| 20 kbps | 100 | 2.778 µs | 15 | 2 | 18 | 50 µs | 88.9% |
| 10 kbps | 200 | 5.556 µs | 15 | 2 | 18 | 100 µs | 88.9% |

**想精确 87.5% 怎么办？** 500 kbps 可以用：

```
Prescaler = 9，BS1 = 6 tq，BS2 = 1 tq，N = 8
tq = 250 ns，位时间 = 2 µs，采样点 = 7/8 = 87.5%
```

代价是 BS2 只有 1 tq，再同步余量小；长总线/低成本晶振时不如 18 tq 稳。**采样点不是越靠后越好，要留再同步余量**。

### 3.5 硬同步与再同步

| 机制 | 触发 | 动作 | 限制 |
|---|---|---|---|
| **硬同步** | 只在 SOF 的隐性→显性边沿 | 直接把位时间复位，让 Sync_Seg 对齐边沿 | 无（每帧一次） |
| **再同步** | 帧内每个隐性→显性边沿 | 边沿晚到：加长 Phase_Seg1；边沿早到：缩短 Phase_Seg2 | 每次最多 `SJW` 个 tq |

```
理想：   |Sync| Prop | Phase1 | Phase2 |
实际：             ↑ 晚到 e=2tq
调整：   |Sync| Prop | Phase1+2tq | Phase2 |   （SJW≥2）
```

**SJW 的意义**：它是"每次允许纠偏的最大量"。太小，晶振误差/传播延迟累积，采样点漂出位边界；太大，对噪声边沿过于敏感。一般 `SJW ≤ BS2`，1 Mbps 短总线取 1 tq，长总线/陶瓷谐振器取 2~4 tq。

### 3.6 传播延迟与"为什么 1 Mbps 只能 40 m"

CAN 是异步总线，发送方发出的位，要经过：

```
发送节点 bxCAN → 收发器 → 线缆 → 接收节点收发器 → 接收节点 bxCAN
```

再算上接收方的采样点，**往返传播延迟必须小于"采样点之前的时间"**。

粗略算 1 Mbps：

```
位时间 1 µs，采样点 87.5% → 采样前有 0.875 µs
收发器环路延迟（TJA1050 tPD 最大约 250 ns）× 2 ≈ 0.5 µs
留给线缆的往返时间 ≈ 0.375 µs
双绞线延迟约 5 ns/m，往返 → 0.375 µs / (2×5 ns/m) ≈ 37.5 m
```

所以 1 Mbps 的 40 m 不是"协议规定"，而是**位时间、采样点、收发器延迟、线缆延迟**共同算出来的。降速到 125 kbps，位时间 8 µs，同样的延迟占比小，距离就能到 500 m。

### 3.7 怎么测位时间

- **示波器**：探头接 CAN_H 和 CAN_L（差分或两路相减），测一个位的宽度；500 kbps 应是 2 µs，1 Mbps 是 1 µs；
- **数 10 位**：测 10 个位的总宽度再除以 10，比测单个位准；
- **ACK 位**：发送方在 ACK 槽发隐性，接收方拉显性，示波器上能看到一个窄的显性脉冲；
- **采样点**：示波器不能直接看，用 CAN 分析仪（它知道自己的采样点）或"逐步改 BS1/BS2 直到刚好出错"来验证；
- **仲裁**：两个节点同时发不同 ID，看输的节点在哪一位停止驱动。

### 3.8 位时间常见错误

| 现象 | 原因 |
|---|---|
| 完全通信不上，错误计数飞涨 | PCLK1 不是 36 MHz / Prescaler 算错 |
| 近距离能通，长线随机错误 | 采样点太靠前 / BS1 没覆盖传播延迟 / 缺终端 |
| 高速时通，低速时不通 | BS1/BS2 配错，或把 `CAN_BS1_x` 当成寄存器原值 |
| 偶尔填充/格式错误 | SJW 太小，晶振误差累积 |
| 两端单独都正常，一起就不行 | 两端波特率/采样点不一致（一个 88.9%，一个 75%） |

## 4. 中断：FIFO 门铃怎么按

### 4.1 中断源总表

| 中断源 | 标志位 | 使能位 | 向量（F103） | 清除方式 |
|---|---|---|---|---|
| 发送邮箱空 | `TSR.RQCP0/1/2` | `TMEIE` | `CAN1_TX_IRQn` | 写 1 清对应 `RQCPx` |
| FIFO0 非空 | `RF0R.FMP0` | `FMPIE0` | `CAN1_RX0_IRQn`（USB_LP） | 读走并 `RFOM0` 释放 |
| FIFO0 满 | `RF0R.FULL0` | `FFIE0` | 同上 | 写 1 清 `FULL0` |
| FIFO0 溢出 | `RF0R.FOVR0` | `FOVIE0` | 同上 | 写 1 清 `FOVR0` |
| FIFO1 非空 | `RF1R.FMP1` | `FMPIE1` | `CAN1_RX1_IRQn` | `RFOM1` |
| FIFO1 满/溢出 | `FULL1/FOVR1` | `FFIE1/FOVIE1` | 同上 | 写 1 |
| 错误警告（≥96） | `ESR.EWGF` | `EWGIE` | `CAN1_SCE_IRQn` | 写 `MSR.ERRI`，ESR 位随状态硬件清 |
| 错误被动（≥128） | `ESR.EPVF` | `EPVIE` | 同上 | 同上 |
| 总线关闭 | `ESR.BOFF` | `BOFIE` | 同上 | 同上 |
| 错误码变化 | `ESR.LEC[2:0]` | `LECIE` | 同上 | 写 `ESR=0` + `MSR.ERRI` |
| 唤醒 | `MSR.WKUI` | `WKUIE` | `CAN1_SCE_IRQn` | 写 1 清 `WKUI` |
| 睡眠 | `MSR.SLAKI` | `SLKIE` | 同上 | 写 1 清 `SLAKI` |
| 错误总中断 | `MSR.ERRI` | `ERRIE` | 同上 | 写 1 清 `ERRI` |

> `CAN_IT_ERR` 不是独立错误源，它是 `MSR.ERRI`，是"有错误发生"的总门铃；具体是哪种错误看 `ESR`。

### 4.2 NVIC 向量（F103）

| 向量 | 处理函数 | 管什么 |
|---|---|---|
| `CAN1_TX_IRQn` | `CAN1_TX_IRQHandler` | 发送邮箱空 |
| `CAN1_RX0_IRQn` | **`USB_LP_CAN1_RX0_IRQHandler`** | FIFO0 |
| `CAN1_RX1_IRQn` | `CAN1_RX1_IRQHandler` | FIFO1 |
| `CAN1_SCE_IRQn` | `CAN1_SCE_IRQHandler` | 错误/唤醒/睡眠 |

> 再次强调：F103 的 CAN1_RX0 和 USB 低优先级共用向量，函数名必须是 `USB_LP_CAN1_RX0_IRQHandler`，写成 `CAN1_RX0_IRQHandler` 就永远进不去。

### 4.3 三个最常用的 ISR 模板

**接收（FIFO0）**：

```c
void USB_LP_CAN1_RX0_IRQHandler(void)
{
    CanRxMsg rx;

    /* FMP 可能 >1，一次中断把 FIFO 读空 */
    while (CAN_MessagePending(CAN1, CAN_FIFO0) > 0)
    {
        CAN_Receive(CAN1, CAN_FIFO0, &rx);   // 读数据 + RFOM 释放
        RingBuffer_Push(&rx);                // 只做拷贝，重活丢主循环
    }
}
```

**发送（邮箱空）**：

```c
void CAN1_TX_IRQHandler(void)
{
    /* 3 个邮箱都可能完成，逐个处理 */
    if (CAN_GetITStatus(CAN1, CAN_IT_TME) != RESET)
    {
        /* 如果你有发送队列：在这里取下一帧 CAN_Transmit */
        CAN_ClearITPendingBit(CAN1, CAN_IT_TME);  // 库函数会清 3 个 RQCP
    }
}
```

> 注意：`CAN_ClearITPendingBit(CAN_IT_TME)` 会把 **3 个邮箱的 RQCP 一起清掉**。如果你同时用多个邮箱，最好直接写对应位，或者在清之前把 3 个邮箱的状态都处理完。

**错误/状态变化（SCE）**：

```c
void CAN1_SCE_IRQHandler(void)
{
    uint32_t esr = CAN1->ESR;
    uint8_t  lec = (esr >> 4) & 0x07;
    uint8_t  tec = (esr >> 24) & 0xFF;
    uint8_t  rec = (esr >> 16) & 0xFF;

    if (esr & CAN_ESR_BOFF) {
        /* bus-off：记录，必要时重新初始化 */
    }
    if (esr & CAN_ESR_EPVF) { /* 进入错误被动 */ }
    if (esr & CAN_ESR_EWGF) { /* 错误警告 */ }

    /* 清 ERRI；EWG/EPV/BOF 由硬件按总线状态清 */
    CAN1->MSR = CAN_MSR_ERRI;
    CAN1->ESR = 0;   // 清 LEC
    (void)lec; (void)tec; (void)rec;
}
```

### 4.4 清除标志的坑（必看）

| 坑 | 后果 | 正确做法 |
|---|---|---|
| TME 中断里不清 `RQCPx` | 中断反复进入（中断风暴） | 写 1 清对应 `RQCPx` |
| `CAN_ClearITPendingBit(CAN_IT_TME)` 清 3 个 | 其他邮箱的完成事件被吞 | 处理完 3 个邮箱再清，或直接写单个位 |
| FIFO 读数据不 `RFOM` | FMP 不减，FIFO 很快满/溢出 | `CAN_Receive` 已带 `RFOM`；自己读寄存器要手动写 `RFOM` |
| 错误中断里只清 `ERRI` | 下次仍会进（如果错误条件还在） | 正常，错误条件消失后硬件清 EWGF/EPVF/BOFF |
| 用 `CAN_GetFlagStatus` 判断中断 | 即使中断没使能也可能读到标志 | 中断里用 `CAN_GetITStatus`（会检查 IER） |

### 4.5 实时性预算：FIFO 只有 3 级

| 波特率 | 8 字节标准帧（108 位） | 3 帧填满 FIFO |
|---|---|---|
| 1 Mbps | 108 µs | 324 µs |
| 500 kbps | 216 µs | 648 µs |
| 250 kbps | 432 µs | 1.30 ms |
| 125 kbps | 864 µs | 2.59 ms |

- 如果 ISR + 主循环处理一帧的时间超过"3 帧时间"，就会 `FOVR` 丢帧；
- ISR 里只做"读 8 字节 + 元数据 + 入环形缓冲"，解析/打印/控制放主循环；
- 不要在 ISR 里 `printf`、浮点运算、长循环；
- 高负载时把 FIFO0/FIFO1 分开：高优先级报文进 FIFO0，低优先级进 FIFO1，两个中断优先级不同。

### 4.6 中断调试清单

1. `CAN_ITConfig` 使能了吗？
2. NVIC `CAN1_RX0_IRQn` 使能了吗？优先级组设了吗？
3. 函数名对不对（`USB_LP_CAN1_RX0_IRQHandler`）？
4. `CAN_GetITStatus` 返回 RESET 还是 SET？
5. FMP 是否真的 >0（用调试器看 `RF0R`）？
6. 清标志了吗？有没有中断风暴？
7. FIFO 是否溢出（`FOVR`）？

## 5. 时间触发通信（TTCM）：给帧盖时间戳

### 5.1 先分清"事件触发"和"时间触发"

| | 事件触发 | 时间触发 |
|---|---|---|
| 什么时候发 | 事件发生就发 | 到约定时刻才发 |
| 冲突 | 靠仲裁，低 ID 赢 | 时间槽预先分配，理论上不冲突 |
| 延迟 | 不确定（取决于总线负载） | 确定、可预测 |
| 同步 | 不需要全局时间 | 需要全局时间同步 |
| 典型 | CANopen PDO、J1939 | TTCAN、车载安全系统 |

用生活打比方：

- 事件触发 = 谁先到谁先上电梯，挤不挤看运气；
- 时间触发 = 每人按时刻表上电梯，几点几分进哪部梯是排好的。

### 5.2 bxCAN 的 TTCM 到底做了什么

**它只做"时间戳"，不做"时刻表调度"。** 这是最容易误解的地方。

使能 `MCR.TTCM` 后：

1. bxCAN 内部有一个 **16 位时间戳计数器**，按 CAN 位时间递增（1 个位时间 = 1 个计数）；
2. **接收**：硬件把接收时刻的计数值写入 `RDTxR.TIME[15:0]`；
3. **发送**：如果 `TDTxR.TGT=1`，硬件把"帧开始发送时"捕获的计数值写进**数据字节 6/7**（`Data[6]=TIME[7:0]`，`Data[7]=TIME[15:8]`），**DLC 必须=8**，否则不发送时间戳；
4. 计数器自由运行、溢出回绕；**没有"到点自动发"的功能**，也没有完整的 TTCAN 参考报文/时间槽状态机。

所以 bxCAN 的 TTCM 是"给你一把带刻度的尺子"，不是"给你一张列车时刻表"。要做真正的时间触发调度，得靠软件（或换支持 TTCAN 的控制器）。

### 5.3 寄存器与库函数

| 寄存器/位 | 位置 | 作用 |
|---|---|---|
| `MCR.TTCM` | bit7 | 使能时间触发通信模式 |
| `TDTxR.TIME[15:0]` | bit31:16 | 发送邮箱时间戳 |
| `TDTxR.TGT` | **bit8** | 发送时是否把时间戳写进最后两字节 |
| `RDTxR.TIME[15:0]` | bit31:16 | 接收帧时间戳 |
| `CAN_TTComModeCmd()` | 库函数 | 置 `TTCM`，并把 3 个发送邮箱的 `TGT` 都置 1 |

标准库初始化：

```c
init.CAN_TTCM = ENABLE;          // CAN_Init 里置 MCR.TTCM
CAN_Init(CAN1, &init);

CAN_TTComModeCmd(CAN1, ENABLE);  // 置 TGT（3 个邮箱）
```

发送时**不用改结构体**，只要 `DLC=8`，硬件会用时间戳覆盖 `Data[6]/Data[7]`：

```c
CanTxMsg tx;
tx.StdId = 0x123;
tx.IDE   = CAN_Id_Standard;
tx.RTR   = CAN_RTR_Data;
tx.DLC   = 8;                     // 必须 8，否则时间戳发不出去
for (uint8_t i = 0; i < 6; i++) tx.Data[i] = i;
// Data[6]/Data[7] 会被硬件替换成时间戳低/高字节
CAN_Transmit(CAN1, &tx);
```

**接收时间戳的坑**：标准库 `CAN_Receive` 只读 `RDTR` 的 DLC 和 FMI，**不读 TIME**，而且读完就 `RFOM` 释放了。所以必须在 `CAN_Receive` **之前**直接读寄存器：

```c
uint16_t ts = (uint16_t)(CAN1->sFIFOMailBox[CAN_FIFO0].RDTR >> 16);
CanRxMsg rx;
CAN_Receive(CAN1, CAN_FIFO0, &rx);   // 这一步会释放 FIFO
// ts 就是接收时间戳
```

> 也可以自己写一个 `CAN_Receive_WithTime()`，按 `CAN_Receive` 的顺序读 RIR/RDTR/RDLR/RDHR，最后写 `RFOM`。

### 5.4 时间戳的分辨率与回绕

- **分辨率 = 1 个位时间**：
  - 1 Mbps → 1 µs；
  - 500 kbps → 2 µs；
  - 125 kbps → 8 µs；
- **16 位回绕周期** = 65536 × 位时间：
  - 1 Mbps → 65.536 ms；
  - 500 kbps → 131.072 ms；
  - 125 kbps → 524.288 ms；
- 所以它只能做**相对时间/短周期**测量；要绝对时间，配合 SysTick/RTC，并处理回绕。

### 5.5 用时间戳做"软时间触发"（思路）

```
1. 选一个节点做时间主站，周期发"参考帧"（带时间戳）
2. 其他节点收到参考帧，记录本地时间戳，算出偏移
3. 每个节点按"参考帧时刻 + 自己的槽偏移"安排发送
4. 发送前比较当前时间戳，到了自己的槽才置 TXRQ
5. 用接收时间戳统计抖动（实际到达 - 计划到达）
```

伪代码：

```c
// 收到参考帧后
uint16_t ref_ts = rx_timestamp;
uint16_t my_slot = ref_ts + MY_OFFSET;

// 主循环/定时器里
if ((uint16_t)(now_ts - my_slot) < 0x8000) {  // 处理回绕
    CAN_Transmit(CAN1, &tx);
}
```

这不是硬实时 TTCAN，但能在软件层做出"近似时间触发"的节拍，适合课程实验/中小项目。

### 5.6 TTCM 和 CANopen SYNC、TTCAN 的关系

| 概念 | 是什么 | 和 TTCM 的关系 |
|---|---|---|
| **CANopen SYNC** | 应用层对象（COB-ID 0x80），主站周期广播，从站收到后同步采样/发送 PDO | 不依赖 TTCM；用普通 CAN 帧即可 |
| **TTCAN（ISO 11898-4）** | 时间触发 CAN，参考报文 + 基本周期 + 时间槽 | bxCAN 的 TTCM 只提供时间戳原语，不是完整 TTCAN |
| **bxCAN TTCM** | 硬件时间戳 + 发送全局时间 | 可用于测量、软同步、抖动统计，不自动调度 |

### 5.7 什么时候用 TTCM

**适合**：

- 测量端到端延迟、节点间抖动；
- 做简单的全局时间同步；
- 课程/竞赛里做"软时间触发"实验；
- 记录每帧的到达时刻，做总线负载/时序分析。

**不适合**：

- 需要硬实时、无仲裁的 TTCAN 调度（要专用控制器/软件协议栈）；
- 需要长时间、高分辨率的绝对时间（分辨率只有 1 个位时间，16 位计数还会回绕）；
- 普通 CANopen/J1939 项目（用 SYNC/时间同步对象更合适）。

## 6. 把五件事串起来：一个最小工程的初始化顺序

```c
void CAN_Init_All(void)
{
    /* 1. 时钟 + GPIO */
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA | RCC_APB2Periph_AFIO, ENABLE);
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_CAN1, ENABLE);
    // PA11=RX(IPU), PA12=TX(AF_PP)

    /* 2. 位时间 + 模式（Normal/Loopback/Silent） */
    CAN_InitTypeDef init;
    CAN_StructInit(&init);
    init.CAN_Prescaler = 4;          // 500 kbps @36MHz
    init.CAN_BS1 = CAN_BS1_15tq;
    init.CAN_BS2 = CAN_BS2_2tq;
    init.CAN_SJW = CAN_SJW_1tq;
    init.CAN_Mode = CAN_Mode_Normal;
    init.CAN_ABOM = ENABLE;
    init.CAN_NART = DISABLE;
    init.CAN_TTCM = DISABLE;         // 要用时间戳再 ENABLE
    CAN_Init(CAN1, &init);

    /* 3. 过滤器（先全收，再收紧） */
    // CAN_Filter_Config();

    /* 4. 中断 + NVIC */
    CAN_ITConfig(CAN1, CAN_IT_FMP0, ENABLE);
    NVIC_EnableIRQ(CAN1_RX0_IRQn);

    /* 5. 如果要时间戳 */
    // CAN_TTComModeCmd(CAN1, ENABLE);
}
```

**检查顺序**：

1. 回环模式 + 全收过滤器 → 自发自收；
2. 回环 + 精确过滤器 → 验证过滤；
3. 正常模式 + 双板 → 验证收发器/线缆/终端；
4. 加中断 → 验证 FIFO/ISR；

## 8. 速查卡

**过滤器位布局（32 位）**

```
31:21 STID[10:0] | 20:3 EXID[17:0] | 2 IDE | 1 RTR | 0 保留
```

**过滤器寄存器**

```
FxR1 = ID（32 位）      FxR2 = 掩码（掩码模式）/ 第二个 ID（列表模式）
FM1R: 0=掩码 1=列表     FS1R: 0=16位 1=32位
FFA1R: 0=FIFO0 1=FIFO1  FA1R: 1=激活
FMR.FINIT=1 才能改
```

**位时间**

```
N = 1 + BS1 + BS2
tq = CAN_Prescaler / fPCLK1
Baud = fPCLK1 / (CAN_Prescaler × N)
SamplePoint = (1 + BS1) / N
```

**模式位**

```
BTR.SILM=1 静默    BTR.LBKM=1 回环    两者都 1 = 静默回环
MCR.TTCM=1 时间戳   TDTxR.TGT=1 发送时间戳（bit8）
```

**中断**

```
TX:  CAN1_TX_IRQHandler
RX0: USB_LP_CAN1_RX0_IRQHandler  ← 反直觉
RX1: CAN1_RX1_IRQHandler
错误: CAN1_SCE_IRQHandler
```

**清除**

```
RQCPx: 写 1
FMP:   读走 + RFOM
FULL/FOVR: 写 1
ERRI:  写 1；EWGF/EPVF/BOFF 随总线状态硬件清
LEC:   写 ESR=0
```
