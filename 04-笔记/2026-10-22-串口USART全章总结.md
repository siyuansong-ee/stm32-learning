# STM32 串口（USART）全章总结 · 详解版

> 基于 9-1 串口发送 + 9-2 串口发送+接收，STM32F103 + 标准库
> 主线：**发送用查询（主动），接收用中断（被动）**——这是串口编程的第一原则。

---

## 一、UART 协议基础（先记住协议，再看外设）

### 异步通信的本质
- **没有时钟线**，双方各自用自己的时钟，靠**波特率**（每秒传多少位）对拍
- 全双工：TX（发）和 RX（收）是两根独立的线

### 一帧的格式（异步串行帧）
```
空闲(高) [起始位0] [D0 D1 ... D7 低位在前] [可选校验] [停止位1] 空闲(高)
```

### 双方必须一致的三件事（不一致 = 乱码）
1. **波特率**（如 9600）
2. **数据位数**（8/9 位）
3. **停止位/校验**（如 8N1 = 8 数据位、无校验、1 停止位）

### 波特率怎么算（寄存器背后）
**USARTDIV = fck / (16 × 波特率)**
- USART1 挂 APB2（72MHz），9600 波特率 → 72M/(16×9600) = 468.75
- 库函数帮你算进 BRR 寄存器，你只填波特率数字

## 二、USART 外设（关键事实）

| 项目 | 内容 |
|---|---|
| USART vs UART | USART 多一个"同步"模式，其余一样（我们只用异步） |
| 资源 | USART1（APB2，72MHz）、USART2/3（APB1） |
| 引脚 | PA9 = TX（**复用推挽**）、PA10 = RX（**浮空或上拉输入**） |
| 关键寄存器 | DR（收发复用同一地址：写=发，读=收）、SR（状态标志） |
| 两个核心标志 | **TXE**（发送寄存器空，可写下一个）、**RXNE**（接收非空，有新数据） |

**DR 寄存器的小魔法**：读写同一个地址，硬件内部把它分成 TDR（写时）和 RDR（读时）——写进去的字节和读出来的字节互不干扰。

## 三、发送：查询方式（9-1）

### 核心原子操作 Serial_SendByte
```c
USART_SendData(USART1, Byte);                              // ① 先写
while(USART_GetFlagStatus(USART1, USART_FLAG_TXE)==RESET); // ② 后等 TXE
```
**为什么"先写后等"**：TDR 初始为空，第一个字节可直接写；写后等 TXE 表示"数据已移进移位寄存器，可装下一个"。
**反过来（先等再写）第一个字节就卡死**——TDR 本来就空，TXE 一直 SET，会先空等一轮。

### 四个函数的递进
| 函数 | 关键点 |
|---|---|
| SendByte | 发 1 字节（所有发送的基石） |
| SendArray | 循环调 SendByte |
| SendString | 发到 **`'\0'`** 为止（C 字符串终止符） |
| SendNumber | `Number/10^(len-i-1)%10 + '0'` 逐位拆 + 转 ASCII |

### printf 重定向（两种方式，都写在你代码里）
1. **fputc 重定向**：标准 printf 底层调 fputc → 接到 SendByte；**需勾 Keil 的 Use MicroLIB**
2. **Serial_Printf 自造**：用 `va_list + sprintf` 自己实现可变参数；不依赖 MicroLIB，更可控

🔗 **串联微机原理**：DOS 09H 调用发字符串以 **`'$'`** 结尾，这里 SendString 以 **`'\0'`** 结尾——同一个"字符串终止符"思想，两个时代。

## 四、接收：中断方式（9-2）

### 为什么接收必须用中断（第一原则）
- **发送是主动的**：你知道什么时候发 → 查询就够（甚至 DMA）
- **接收是被动的**：数据随时可能来，你不能让 CPU 空等 → **必须中断**

### 中断接收的完整链路（六步）
```
① USART_ITConfig(RXNE, ENABLE)   ← 开接收中断（外设级开关）
② NVIC 使能 USART1_IRQn          ← 开 NVIC（内核级开关）
③ 数据到来 → 硬件置 RXNE=1
④ 触发中断 → 进 USART1_IRQHandler
⑤ 读 DR（自动清 RXNE）→ 存进变量 → 置 flag
⑥ main 轮询 flag → 取出数据 → 处理
```

### "中断置 flag，main 处理"——这章最重要的设计模式
```c
void USART1_IRQHandler(void) {          // 中断里：只做最少的活
    if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET) {
        Serial_RxData = USART_ReceiveData(USART1);  // 读数据（读即清标志）
        Serial_RxFlag = 1;                          // 置 flag
    }
}
// main 里：轮询 flag，处理数据
```
**为什么中断服务函数要短**：中断期间主程序被冻结，你在中断里做耗时的事（比如 OLED 显示），主程序就卡死。所以**中断只"接数据+置标志"，业务逻辑丢给 main**——这是嵌入式面试必问的设计原则。

### 三个配套函数
- `Serial_GetRxFlag()`：**读即清**——返回 1 并同时把 flag 清零，防止同一个数据被处理两次
- `Serial_GetRxData()`：取走数据
- `USART1_IRQHandler`：中断服务函数（名字必须和启动文件一致，又是那个铁律）

### GetITStatus vs GetFlagStatus（容易混，值得记）
| 函数 | 检查什么 |
|---|---|
| `GetFlagStatus(FLAG_RXNE)` | 只看 SR 的 RXNE 标志位 |
| `GetITStatus(IT_RXNE)` | 看 RXNE 标志 **且** 中断使能位都置 1 |

**中断服务函数里应该用 GetITStatus**（确认"这个中断确实是开的"）。两者在单中断源时结果一样，但规范写法是 GetITStatus 配 IT_RXNE。

## 五、三种收发方式对比（串联微机原理）

| 方式 | 谁处理 | 适用 | 对应微机原理 |
|---|---|---|---|
| **查询**（9-1 发送） | CPU 轮询标志 | 主动发送、简单场景 | 程序查询方式 |
| **中断**（9-2 接收） | 外设打断 CPU | 被动接收、随机数据 | 中断方式 |
| **DMA**（后面） | 硬件搬运 | 大批量数据 | DMA 方式 |

## 六、常见坑（条条真实）

1. **引脚配错**：PA9 忘复用推挽 / PA10 忘输入模式
2. **波特率不一致** → 乱码（串口助手和代码必须一致）
3. **发送"先等再写"** → 第一个字节卡死
4. **中断里忘清标志** → 反复进中断（RXNE 读 DR 自动清，但要记住）
5. **中断函数名拼错**（USART1_IRQHandler）→ 覆盖不了弱定义
6. **TXE/RXNE 混淆**：发等 TXE，收等 RXNE
7. **中断服务函数里做耗时操作** → 主程序卡死（flag 模式解决）

## 七、与微机原理 8251 的对照

| 8251 | STM32 USART |
|---|---|
| 方式字（波特率/位数/停止位） | USART_Init 结构体 |
| 命令字（允许收/发） | USART_Cmd + USART_ITConfig |
| 异步帧格式 | 完全一样 |
| 字符串以 '$' 结尾（DOS） | 字符串以 '\0' 结尾（C） |
