# 09 · I2C 与 MPU6050

> 你的代码：`10-1软件I2C读写MPU6050\hardware\MyI2C.c` + `MPU6050.c`（软件时序）、
> `10-2硬件I2C读写MPU6050\hardware\MPU6050.c`（硬件外设+事件序列）、`4-1OLED` 的软件 I2C。
> 手册：RM0008 §20（I2C）、§20.6（寄存器）；MPU6050 Register Map（PS-MPU-6000A）。

## 9.1 协议层：四个"条件"与一个应答（先于一切寄存器）

I2C 协议只有这么几个原子动作（对着 MyI2C.c 看）：

| 动作 | 定义 | 你的代码 |
|---|---|---|
| START | **SCL 高电平期间 SDA 高→低** | MyI2C_Start L44-50 |
| STOP | **SCL 高电平期间 SDA 低→高** | MyI2C_Stop L53-58 |
| 数据位 | SCL 低时换数据，**SCL 高时数据必须稳定**（从机采样） | SendByte L61-70 |
| ACK | 第 9 个时钟，接收方把 SDA 拉低 | ReceiveAck L99-109 |
| 重复起始 | 不产生 STOP 的 START（换方向不释放总线） | MPU6050_ReadReg L33 |

**为什么 START/STOP 定义成"SCL 高时 SDA 跳变"？** 因为数据位规定"SCL 高时 SDA 不许变"——于是 SDA 在 SCL 高电平期间的跳变就成了**唯一可识别的特殊信号**，协议用"违反数据规则"来定义控制信号。这是 I2C 设计里最优雅的一笔，面试讲出来必加分。

**总线电平靠开漏+上拉**（01 篇埋过伏笔）：所有设备只拉低不拉高，谁输出 0 谁把线拽下去 = **线与**。SCL 同理——慢速从机（如某些 EEPROM）可以主动拉低 SCL 拖慢时钟，这叫 **时钟拉伸**（clock stretching），主从同步的高级话题。

## 9.2 你的软件 I2C：逐行算时序

MyI2C.c 的核心是 `MyI2C_W_SCL/W_SDA` 里**每个电平变化后 `delay_us(10)`**：半个周期 10µs → 时钟周期约 20µs → **SCL ≈ 50kHz 上限内、实际约 20-30kHz**（加上 GPIO 翻转本身的时间）。

- 10µs 延时是**用时间换稳妥**：MPU6050 的 I2C 上限 400kHz，软件翻转 GPIO 根本到不了上限，慢反而是优点（信号完整、抗干扰）；
- 缺点写脸上：**每 bit 阻塞 CPU 20µs**，读 14 字节一次要 ~2.4ms 的纯忙等（10-1 的 GetData 读六轴 ≈ 一帧 2.5ms）。main 里还有 OLED 刷新时，总线时间和 CPU 时间都被 I2C 吃掉——这就是 10-2 硬件 I2C 存在的意义；
- 你 `MyI2C_ReceiveAck` 里 `delay_us(1)` 等从机把 SDA 拉稳——细节正确；
- 注意到 `MPU6050_ReadReg` L33 的**重复起始**（`MyI2C_Start` 开头先 `W_SDA(1)` 兼容重复起始场景，L46 注释）——读寄存器的标准序列"写地址+寄存器号 → 重复起始 → 读地址"你写的是教科书版本。

## 9.3 从机地址与 MPU6050 寄存器

- **地址字节**：7 位从机地址 + 1 位方向。MPU6050 的 7 位地址 0x68（AD0 引脚接地），写方向 = `0x68<<1 | 0 = 0xD0`，读方向 = 0xD1——你的 `#define MPU6050_ADDRESS 0xD0` 注释解释得分毫不差。OLED 的 0x78 同理（SSD1306 7 位地址 0x3C）；
- **写寄存器时序**：START → 0xD0+ACK → 寄存器号+ACK → 数据+ACK → STOP（`MPU6050_WriteReg`）；
- **MPU6050_Init 的寄存器含义**（对 Register Map 逐条）：

| 寄存器 | 值 | 意义 |
|---|---|---|
| PWR_MGMT_1=0x01 | 清 SLEEP，CLKSEL=1 | 时钟源选 X 轴陀螺 PLL（陀螺基准时钟，比内部 RC 稳） |
| SMPLRT_DIV=0x09 | 采样率 = 1kHz/(1+9) | 100Hz 采样 |
| CONFIG=0x06 | DLPF_CFG=6 | 低通 5Hz 带宽，抑制机械振动噪声 |
| GYRO_CONFIG=0x18 | FS_SEL=3 | ±2000°/s，灵敏度 16.4 LSB/(°/s) |
| ACCEL_CONFIG=0x18 | AFS_SEL=3 | ±16g，灵敏度 2048 LSB/g |
| WHO_AM_I(0x75) | 读回 0x68 | **上电自检**：读不到说明接线/地址/总线有问题——你 GetID 的用途 |

- **连续读 14 字节**（10-1 `MPU6050_GetData`）：从 0x3B 一口气读 14 字节。MPU6050 硬件支持**地址自增读**，一次总线事务拿齐六轴——比 6 次单读快一个数量级，且六轴是同一采样时刻的快照。你 10-2 的 `MPU6050_GetData` 是逐个寄存器读（12 次总线事务），**数据一致性差**（X 轴和 Z 轴不是同一时刻采的）——这是 10-2 相对 10-1 唯一退步的地方，改法：把 10-1 的连续读逻辑套到硬件 I2C 上；
- **16 位拼接**：高字节在前，`(DataH<<8)|DataL` 后转 int16_t——MPU6050 数据寄存器是大端序，芯片手册的字节序约定（对比 W25Q64 的 24 位地址也是先发高位）。

## 9.4 硬件 I2C 的寄存器与事件序列（10-2）

10-2 用 I2C2（PB10/PB11，AF_OD 复用开漏）。`I2C_Init` 落地写了四个寄存器：

| 寄存器 | 你的参数 | 算出来的值 |
|---|---|---|
| CR2.FREQ[5:0] | 自动取 PCLK1 | 36（MHz） |
| CCR | 50kHz、DutyCycle_2 | **CCR = 36MHz/(2×50kHz) = 360**（标准模式 Tlow=Thigh） |
| TRISE | 自动 | 上升时间补偿 = 36MHz/1MHz + 1 ≈ 37 |
| OAR1 | OwnAddress1=0x00 | 本机作为主机的地址（主机模式用不上） |

**CR1 的四个控制位**（面试要能背）：PE（总使能）、START/STOP（软件置位产生条件，硬件完成后自动清）、ACK（应答使能）、SWRST（软件复位，卡死时救命）。

**事件序列**（你的 MPU6050_WriteReg 就是标准主发送流程，对 SR1/SR2 的位）：

```
START → 等 EV5 (SB=1: 起始已发出)
发送地址(写) → 等 EV6 (ADDR=1: 从机已应答) ← 读 SR1+SR2 清 ADDR
写寄存器号 → 等 EV8_2 (TxE=1: DR 空,可以写下一个)
写数据 → 等 EV8_1 (BTF=1: 移位完成)
STOP
```

`I2C_CheckEvent` 内部就是"读 SR1、读 SR2、按掩码比较"——**读 SR1 再读 SR2 的动作本身清 ADDR 标志**（和 USART 的"先 SR 后 DR"清 ORE 同款套路，清标志全家桶第四位成员）。

## 9.5 F1 硬件 I2C 的著名坑（面试超高频）

1. **BUSY 卡死**：从机在 SCL/SDA 中间态复位（如 MPU6050 断电），I2C 外设 BUSY=1 且无法产生 START → 外设永久罢工。恢复三板斧（AN2824 思路）：① `I2C_SWResetCmd` 软复位；② 把 SCL/SDA 切成 GPIO 输出，手动翻 9 个时钟把从机状态机赶回空闲；③ 重新初始化。**你的 `MPU6050_WaitEvent` 加超时（L7-19）是对的方向**——超时返回而不是死等，但超时后要调用恢复流程才闭环；
2. **超时保护不一致**：你的 `MPU6050_WriteReg` 用了带超时的 WaitEvent，**`MPU6050_ReadReg` 却用裸 `while(I2C_CheckEvent...)`**（L43-60）——传感器拔掉读方向会死循环。**工程体检项**：统一超时策略；
3. **单字节读的顺序**：`ReadReg` 里先 `I2C_AcknowledgeConfig(DISABLE)` + STOP 再等 RXNE 读 DR——单字节读必须先"预告 NACK+STOP"再读数据（否则多读一拍挂住总线）。你的顺序是对的；
4. 为什么很多项目放弃硬件 I2C 用软件模拟？因为 F1 I2C 的这几个坑 + 勘误表（ES096 系列）让移植成本高——**"用不用硬件 I2C"本身就是面试观点题**：你的答案可以是"小数据量+追求通用性用软件模拟；大数据量+有时间抠勘误用硬件+DMA"。

## 9.6 面试官视角

- "画出 I2C 读写一个寄存器字节的完整波形。"→ START/地址/ACK/寄存器/ACK/数据/ACK/STOP，SCL 与 SDA 的时序约束。
- "为什么 I2C 引脚必须开漏？"→ 线与 + 时钟拉伸；推挽会打架。
- "ACK 和 NACK 谁拉低 SDA？"→ 接收方拉低（主机发数据时从机 ACK；主机收数据时主机 ACK/NACK）。
- "硬件 I2C 的 EV5/EV6/EV8 是什么？"→ SB/ADDR/TxE-BTF 事件，读 SR1+SR2 清 ADDR。
- "F1 硬件 I2C 卡死怎么办？"→ 超时 + SWRST + 9 时钟恢复。
- "读六轴为什么要连续读 14 字节？"→ 地址自增 + 同一时刻快照 + 总线效率。
