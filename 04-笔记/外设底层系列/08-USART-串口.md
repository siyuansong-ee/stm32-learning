# 08 · USART 串口

> 你的代码：`9-1串口发送\hardware\Serial.c`（printf 重定向）、`9-2`（收发）、
> `9-3串口收发HEX数据包`、`9-4串口收发文本数据包`（两个状态机版本）。
> 手册：RM0008 §24（USART）、§24.3（功能描述）、§24.6（寄存器）。

## 8.1 你的代码长这样

```c
// 9-4 Serial.c：9600-8-N-1，RXNE 中断 + 三状态状态机
USART_InitStructure.USART_BaudRate = 9600;
USART_InitStructure.USART_WordLength = USART_WordLength_8b;   // 8 数据位
USART_InitStructure.USART_StopBits = USART_StopBits_1;        // 1 停止位
USART_InitStructure.USART_Parity = USART_Parity_No;           // 无校验
USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);   // 每收 1 字节进一次中断

void Serial_SendByte(uint8_t Byte)
{ USART_SendData(USART1, Byte);                       // 写 DR（发送侧 = TDR）
  while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET); }  // 等 TDR 空
```

## 8.2 帧格式：线上的一字节长什么样（RM0008 §24.3.1）

```
空闲(高) ──┐ ┌─┬─┬─┬─┬─┬─┬─┬─┐ ┌────
           └─┘D0│D1│…│D7│[P]└─┘ 停止位(高)
           起始位(低,1位)   可选的校验位
```

"9600-8-N-1"= 9600 波特、8 数据位、无校验、1 停止位。**波特率 = 每秒 bit 数**（9600 波特下每 bit 104.2µs，一帧 10 bit = 1.04ms）。发送端和接收端**没有时钟线**，靠约定波特率各自计时——所以两端波特率必须一致（误差 <3% 可容忍），这是异步通信的本质。

## 8.3 BRR 波特率寄存器：468.75 是怎么来的（RM0008 §24.3.2）

F1 的 USART 用 **16 倍过采样**：内部以 16×波特率的时钟在每个 bit 中间采样（取第 8/9/10 个采样点的多数票），抗毛刺。公式：

```
USARTDIV = fCK / (16 × Baud) = 72MHz / (16 × 9600) = 468.75
BRR = 整数部分 468 (0x1D4) + 小数部分 0.75 × 16 = 12 (0xC) → BRR = 0x1D4C
```

`USART_Init` 内部就是按这个公式算好写 CR 的（它还顺手处理了 8 倍过采样的情况）。三个由此引出的问题：

1. **为什么波特率是离散的**：BRR 只有 4 位小数，某些波特率配不精确（如 115200 → 39.0625，小数 0.0625×16=1，误差 0.06% 可接受；但 250000 之类误差会爆表）。**算误差公式**：(实际-目标)/目标，>3% 就收不到数据——面试笔试题常客；
2. **fCK 是哪条总线**：USART1 在 APB2（72MHz）、USART2/3 在 APB1（36MHz）——同一波特率在两处算出的 BRR 不同。你只用了 USART1；
3. 过采样 16→8（OVER8=1）时小数只有 3 位，高速率下用。

## 8.4 发送通路：TDR → 移位寄存器 → TX 引脚

```
CPU 写 DR ──► TDR(发送数据寄存器) ──► [TXE=1 表示 TDR 空，可以写下一个]
                    │ 硬件自动
                    ▼
             移位寄存器 ──► 按位挪到 TX 引脚（LSB 先出）
                   [TC=1 表示移位寄存器也空了 = 线上完全发完]
```

- **TXE vs TC**（必考）：TXE=1 只说明"你可以再写一字节进 TDR"，此时上一字节**可能还在移位寄存器里发**；TC=1 才说明"线都发完了"。你 `Serial_SendByte` 等 TXE 是连续发的标准写法（TDR 一空立刻填，移位寄存器不停摆 = 全速）；要确认"发完再做别的"（如关电源、切 RS485 方向）必须等 **TC**；
- 写 DR 会**自动清 TXE**（硬件知道 TDR 又满了）。

## 8.5 接收通路与四个标志：RXNE/ORE/IDLE/FE

```
RX 引脚 ──► 移位寄存器（16 倍过采样逐 bit 收）──► RDR(接收数据寄存器)
                                          [RXNE=1：RDR 有新数据，读 DR 自动清]
```

- **RXNE**：你 ISR 里 `USART_ReceiveData` 读 DR 的动作**同时清 RXNE**（读即清，与 ADC 的 EOC 同款、与 TIM 的写 0 清不同款——"清标志全家桶"第三位成员）；
- **ORE 溢出**（你目前没处理，产品级必修）：RDR 里的数据还没读，新一帧又到了 → 新数据**被丢弃**、ORE=1。清法特殊：**先读 SR 再读 DR**。建议你的 ISR 开头加：

```c
if (USART_GetFlagStatus(USART1, USART_FLAG_ORE) == SET)   // 溢出发生过
{ USART_ReceiveData(USART1); }                            // 读 SR+DR 清掉，继续跑
```

不处理 ORE 的症状：**高速连续发送时接收随机丢字节**（因为状态机停在某个态没读 DR，溢出了）。

- **IDLE**：线上空闲（一整个帧时间都是高电平）→ 可做"帧结束"判定（Modbus 常用），配合 DMA 收变长帧是经典组合；
- **FE/PE/NE**：帧错误/校验错误/噪声错误——你 9-4 没开校验所以 PE 用不上，但知道"出错标志也要读 SR+DR 清"即可。

## 8.6 你的状态机为什么是对的（9-3 vs 9-4 对比）

9-3（HEX 包）：`0xFF + 4字节 + 0xFE`，固定长度；9-4（文本包）：`@ + 正文 + \r\n`，变长 + 边界保护。两个都是"ISR 里只做最小编码、重活丢 main"的典范（内核系列 03 篇表扬过）。底层视角补三点：

1. **状态机变量用 static**（ISR 局部 static）：编译器放 ZI 段，不进栈——ISR 栈开销只有返回地址级；
2. **9-4 L108 的边界检查 `pRxPacket < SIZE-1`**：宁可截断不越界（对比 04 篇内核文档里"越界写冲栈"的灾难），L105 补 `'\0'` 防 strcmp 读越界——这两行是你全仓库最"工程化"的两行防御代码；
3. **丢包策略**：9-3 的 case 2 里"包尾丢了这个字节当新包头就地重同步"，是对"串口没有可靠传输"的正确态度——**上层要么加校验重传，要么接受丢包**，这是协议设计的分水岭（面试可主动展开）。

## 8.7 printf 重定向的底层：fputc 与半主机

9-1 的 `int fputc(int ch, FILE *f) { Serial_SendByte(ch); return ch; }` 重定向原理：

- 标准库的 printf 最终调用 `fputc` 输出字符——**链接器链接的是你定义的 fputc**（同名强符号覆盖库里的弱符号，又是 WEAK 机制，内核系列 01 篇联动）；
- **Keil 上 printf 卡死的经典原因**：默认 fputc 走**半主机 semihosting**——通过 `BKPT 0xAB` 断点指令把字符交给调试器。没有调试器连接时 CPU 卡在断点上 → 程序"死"在第一个 printf。解决：勾 Use MicroLIB（MicroLIB 的 fputc 默认就是用户重定向版）或重写 `_sys_*` 系列——**"printf 卡死"是每个 Keil 新手的成人礼，面试聊出来说明你真做过**；
- 你的 `Serial_Printf` 用 `sprintf` 到 100 字节栈缓冲再发送：**100 字节局部数组压栈**，配合 1KB 总栈深要留意嵌套深度（内核系列 04 篇的栈溢出话题）。

## 8.8 面试官视角

- "TXE 和 TC 什么区别？什么时候等谁？"→ TDR 空 vs 发送机完全空闲；连续发等 TXE，确认发完等 TC。
- "115200 波特率在 72MHz 下误差多少？怎么算？"→ 468.75 那套公式逆运算。
- "RXNE 和 ORE 分别怎么清？"→ RXNE 读 DR 清；ORE 先读 SR 再读 DR。
- "接收溢出丢字节怎么排查？"→ ISR 里有没有读 DR、处理时长是否大于字节间隔（9600→1ms，115200→86.8µs）。
- "printf 为什么卡死？"→ 半主机 BKPT；MicroLIB/重定向。
- "串口协议怎么保证可靠性？"→ 校验和/CRC + 序号 + 重传，或接受丢包语义；9-3/9-4 的帧头尾是"同步层"不是"可靠层"。
